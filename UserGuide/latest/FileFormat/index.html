    File Format

    A TsFile stores time series data in columns. Writers append data in device groups, then write the indexes at the end of the file. Readers usually work in the opposite direction: they open the footer, look up a series, and seek to the Chunks that contain its values.

    This guide describes the v4 file layout, identified by version byte 0x04. It covers the file structures and how they fit together. The encoding chapter gives codec identifiers and the PLAIN layout; the bit layouts of the other value codecs are outside its scope.

    Scope and Terminology

    Data has three levels of organization within a file:

    • A Page holds a batch of encoded values. Each Page is compressed independently.
    • A Chunk holds the Pages of one physical column. Its header identifies the data type, encoding, and compression method.
    • A Chunk Group holds a batch of Chunks for one device. The same device can appear in several Chunk Groups as the writer flushes more data.

    In non-aligned data, each measurement stores its own timestamps alongside its values. In aligned data, a Time Chunk stores the timestamps shared by several Value Chunks. A bitmap in each Value Page identifies the positions that have values. Data Pages explains both layouts.

    Physical Regions

    The file begins with the six-byte magic string TsFile and a one-byte version. An optional file encryption header follows for Page AEAD files. The data section ends at a single 0x02 separator; indexes and file metadata follow it. The last ten bytes hold the metadata length and the trailing magic string.

    The table below uses these names:

    • F: total file length.
    • L: serialized length of TsFileMetadata, stored in the four-byte trailing length field.
    • E: total serialized length of the optional encryption header, or 0 when absent.
    • data_start = 7 + E: start of the data section.
    • meta_offset: separator offset, stored inside TsFileMetadata.

    All offsets are absolute, starting at the first byte of the file. The table uses inclusive intervals; [start, end) elsewhere denotes a half-open interval. A length excludes its own length field unless stated otherwise. The optional-header interval is absent when E = 0.

    Timeseries Metadata and index nodes can be interleaved in the indexed metadata section. Readers follow their offsets rather than assuming a fixed physical order. TsFileMetadata has no marker of its own: its length locates it from the end of the file.

    Write Model

    A writer appends Chunk Groups, then writes the indexes and footer when it finishes the file. Page sizes, flush thresholds, and index fanout affect where structures begin and end, but readers can recover those boundaries from headers and offsets. Timestamp units and non-aligned time encoding need the shared context described in Configurations.

    Both magic strings use the same bytes:

    54 73 46 69 6c 65    # "TsFile"

    Metadata-first Read Algorithm

    A reader can locate the requested series without scanning the data section:

    1. Check the leading magic and version. Inspect offset 7 for an optional file encryption header, which determines how Chunk Headers and Page bodies are parsed.
    2. Check the tail magic, read L at F - 10, and calculate file_metadata_pos = F - 10 - L.
    3. Read TsFileMetadata and check that meta_offset points to the separator.
    4. Optionally check the complete path in the Bloom filter. Use a negative result only when the writer's charset, path construction, and hash behavior are known to match.
    5. Follow the table/device index, then the measurement index, to find the series metadata.
    6. Use the series and Chunk Statistics to select Chunk offsets. Seek to those Chunks and use any Page Statistics to narrow the selection further.
    7. Read the selected Page bodies, decrypt when required, decompress, and decode their streams.

    This avoids reading the payloads of unrelated Pages. A single-Page Chunk omits Page Statistics, so pruning at that level relies on the Chunk or series Statistics instead.

    Structural Invariants

    The main relationships to check when reading are:

    • Both magic strings and the version are valid.
    • A file encryption header, when present, appears once at offset 7; its length and version are valid.
    • 0 <= L <= F - 10, and file_metadata_pos lies after the separator.
    • A Chunk's Pages occupy exactly data_size bytes after its complete Header.
    • Each non-empty Page body occupies exactly compressed_size bytes within that Chunk.
    • Index offsets are monotonic (non-decreasing) within a node and do not exceed end_offset.
    • An aligned Value Page covers the same positions as the Time Page with the same ordinal; its position_count equals the Time Page's position count.

    A violation is a format error.

    Binary Representation describes the common length and offset checks. Encryption adds the authentication checks for Page AEAD. Marker bytes have meaning only at structure boundaries; the same bytes can occur inside a Page body.
